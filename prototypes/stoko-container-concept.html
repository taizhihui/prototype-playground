Container Concept · STOKO

From return requests
to outcomes protected

For most SMS marketing tools, post-purchase is an afterthought — a review request on a timer, maybe a win-back sequence months later. For Stoko, post-purchase is where most of the value lives and most of the cost is lost.

The container model changes what AI Journey does after the purchase. A CX operator describes the outcome they want — reduce returns, educate new buyers, capture reviews at the right moment. The container handles the rest: proactive check-ins, return interceptions, medical boundary detection, review timing.

Here's what that looks like for Stoko.

Container Intelligence
Behavioral inputs that drive this container's decisions
Return Window
0–30d
Peak return risk period
Stoko offers a 30-day guarantee. Most returns happen when buyers can't figure out the break-in period in the first two weeks. Container weights all engagement signals highest in this window — day 7 is the proactive check-in target.
Fit Blockers
5 patterns
From 100 AI call summaries
Can't get above the knee · Break-in timeline confusion · Dial release technique · Patella strap position · Size uncertainty. Container carries precise, tested responses to each — not a FAQ page redirect.
Suppression Logic
5 conditions
When the container holds
Return request in human queue · Active escalated support ticket · Medical condition mentioned (routes to Escalate) · Message sent within 5 days · Shopper replied "not now" within 48h. Container holds and re-evaluates — does not skip.
Signal Hierarchy
Return › Contact › Silence
Urgency ranking
Container leads with the highest-urgency signal. Return request outranks inbound contact — purchase decision is already reversing. Inbound contact outranks silence — customer is asking for help. Proactive check-in fires into silence at day 7.
The Shift

Today vs. container

Today
Buyer can't get the product on → emails support → receives a macro linking to the FAQ page they've already read.
Return request filed → processed by a human agent without diagnosing the underlying fit issue first.
Review request fires on a 14-day timer, to all buyers, regardless of whether the experience was positive.
Medical questions handled inconsistently depending on which macro gets pulled and how it gets personalized.
Container
Container checks in proactively at day 7 — before frustration becomes an inbound contact or a return request.
Return intent detected → container intercepts and diagnoses the fit issue before the request reaches a human.
Review prompt fires only when positive engagement signals confirm the buyer is satisfied — not on a schedule.
Medical mentions trigger automatic detection and a compliant, consistent response every time.
